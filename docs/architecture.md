# Архитектура «Местечка»

## Слои и зависимости

```
apps/miniapp ─┐                          ┌─ packages/ui (дизайн-система, без предметной области)
apps/cabinet ─┼─ packages/booking-ui ────┤
              │                          └─ packages/i18n (переводы, форматтеры)
              └─ @mestechko/contracts/client (типы + лёгкий клиент, без схем)

apps/api ── modules/<контекст>/{api → application → domain-порты ← infrastructure}
         └─ platform (конфигурация, БД, очереди, наблюдаемость, HTTP)

packages/contracts ── схемы Zod: источник типов API и OpenAPI
packages/domain ──── чистый домен: время, графики, календарь, доступность, вертикали, правила
```

- **Домен** (`packages/domain`) не знает о базе, сети, фреймворках и даже о Zod — это закреплено
  правилом ESLint. Здесь движок доступности, графики, политика производственного календаря,
  реестры вертикалей, статусов, ролей, каналов, источников записи и денег.
- **Приложение** (`modules/*/application`) описывает сценарии и порты. Импорт адаптеров, Nest,
  Kysely, Redis из этого слоя запрещён линтером.
- **Инфраструктура** реализует порты: Kysely-репозитории, адаптер isdayoff.ru, BullMQ, scrypt,
  подпись данных Telegram.
- **API** — контроллеры NestJS, связанные с контрактом через `@ContractRoute`.
- **Корень композиции** — `apps/api/src/app.module.ts`: модули собирают зависимости фабриками,
  доменные и прикладные классы не помечены декораторами фреймворка.

Модули API: `tenancy` (бизнесы, членство, доступ), `identity` (кабинет, сессии, Telegram),
`catalog`, `scheduling` (графики, производственный календарь, фоновые задачи), `clients`,
`booking` (доступность, создание записи, «мои записи», расписание и записи кабинета), `media`.
Граф зависимостей модулей ацикличен: `booking → catalog, scheduling, clients, tenancy`.

## Ключевые решения

**Движок доступности — чистая функция.** На вход — услуги, кандидаты с графиками и
персональными условиями, ресурсы, занятость, производственный календарь, правила, «сейчас»;
на выход — свободные старты по дням и планы бронирования. Учитывает перерывы, буферы до и после
(на краях комбинации услуг), длительности и комбинации, ресурсы разных типов, часовые пояса
и переходы на летнее время, сменные графики 2/2, исключения на даты. Время внутри — целые
миллисекунды, стены часов — Temporal (полифил, единая точка импорта).

**Двойная бронь невозможна в базе.** `booking_items.occupied` — `tstzrange` с ограничениями
`EXCLUDE USING gist` по сотруднику и по ресурсу для статусов, занимающих время. Статус позиции
зеркалит статус записи через составной внешний ключ с `ON UPDATE CASCADE`, поэтому их не нужно
синхронизировать в коде. Тест сверяет предикат ограничения с доменным реестром статусов.
Создание записи пробует план, а при конфликте перечитывает занятость и планирует заново
(сохранённая точка транзакции откатывает только неудачную попытку).

**Мультитенантность в два слоя.** Каждая таблица тенанта содержит `business_id`, ссылки между
ними — составные ключи `(business_id, id)`, так что чужой id не подставить. Плюс row-level
security: транзакция тенанта выставляет `app.business_id`, политики проверяют чтение и запись,
приложение подключается ролью без обхода RLS. Репозитории берут транзакцию из unit of work и
падают вне контекста тенанта.

**Контракты — схемы Zod.** Из них выводятся типы для сервера и клиентов, сервер валидирует
вход и сериализует ответ через схему (лишние поля не утекают), генерируются OpenAPI и лёгкий
манифест маршрутов для браузера: фронтенды не тянут Zod и libphonenumber в стартовый бандл.
Гейт проверяет, что сгенерированные артефакты актуальны. Типы таблиц Kysely генерируются из
мигрированной базы (`db:codegen --verify` в CI).

**Идемпотентность.** Создание записи требует `Idempotency-Key`; уникальность
`(business_id, client_id, idempotency_key)` в базе гарантирует одну запись на ключ даже при
параллельных запросах. Фоновые задачи схлопываются по ключу дедупликации BullMQ.

**Производственный календарь.** Порт `ProductionCalendarSource` с адаптером isdayoff.ru
(таймаут, разбор кодов праздников и сокращённых дней). Годы хранятся в PostgreSQL с ревизией,
которая растёт только при изменении данных. Синхронизация — задачи BullMQ: ежедневная по
расписанию и по требованию, если года ещё нет. Как бизнес следует календарю (закрыт в праздники,
сокращает предпраздничные дни) — политика вертикали с переопределениями бизнеса.

**Вертикали — записи реестра.** Словарь (мастер/врач/механик, кресло/кабинет/пост), типы
ресурсов, типовые услуги, правила записи (шаг сетки, горизонт, буферы, предоплата, повторные
визиты, политика календаря, стратегия выбора «любого» сотрудника). Новая вертикаль — одна
запись и переводы; тест подключает «спортшколу» без правки кода.

**Авторизация.** Mini App: каждый запрос несёт `Authorization: tma <initData>`, сервер
проверяет HMAC по схеме Telegram и свежесть по часам приложения. Кабинет: собственные сессии —
случайный токен в HttpOnly-cookie, в базе только его SHA-256, скользящий срок жизни, scrypt для
паролей, ограничение попыток входа в Redis. Права — реестр ролей с областями `schedule` и
`bookings` и охватом `own`/`all`.

**Эмулятор Telegram для демо.** Вне Telegram Mini App запускается через `mockTelegramEnv` из
SDK с данными запуска, подписанными сервером демо-ключом. Приложение вызывает только API SDK
(MainButton, BackButton, haptics), эмулятор перехватывает эти вызовы и рисует «хром» Telegram,
а нажатия возвращает в SDK событиями — один путь кода для Telegram и демо.

**Наблюдаемость.** Структурные логи pino с id запроса, пользователем, тенантом и trace id;
метрики OpenTelemetry (HTTP, бизнес-счётчики) на `/metrics` для Prometheus; трассы HTTP и
PostgreSQL выгружаются по OTLP, если задан коллектор. Готовность — `/health/ready`.

## Выбор технологий

- **Кабинет на Vite, а не Next.js.** Кабинет — приложение за авторизацией без SEO; данные
  приходят из отдельного API; серверный рендеринг не даёт выгоды, а добавил бы второй серверный
  рантайм. Vite даёт статическую сборку, общий с Mini App инструментарий и дизайн-систему.
- **TypeScript 6.0.** TypeScript 7 (нативный) уже вышел, но typescript-eslint поддерживает
  только < 6.1: типизированный линт важнее.
- **SDK Telegram — `@tma.js/*`.** Это официальный SDK проекта Telegram Mini Apps; пакеты
  `@telegram-apps/*` переименованы и помечены авторами как неподдерживаемые.
- **Kysely + SQL-миграции.** Ограничения уровня PostgreSQL (exclusion, RLS, составные ключи)
  выражаются напрямую, типы генерируются из схемы.
- **Base UI** — доступные примитивы (select, dialog, toast, radio) для дизайн-системы.
- **OpenTelemetry для метрик** вместо prom-client: последний заменён авторами.

## Гейты

`pnpm gate`: файл ≤ 700 строк и папка ≤ 15 файлов исходников, только токены дизайн-системы
в стилях и разметке, Prettier, ESLint (strict type-checked + границы слоёв), typecheck всех
пакетов, актуальность OpenAPI и манифеста, unit-тесты. CI дополнительно гоняет интеграционные
тесты на PostgreSQL и Redis, сверку типов БД со схемой и полный seed.
